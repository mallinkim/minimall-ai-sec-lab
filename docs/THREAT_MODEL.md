# THREAT_MODEL — MiniMall AI 도우미 위협 모델 (Mission 0 → 계속 갱신)

> 완벽한 답이 아니라 **놓치지 않기 위한 질문 목록**입니다. 기능은 'AI 도우미'(상품 검색 · 주문 조회 · 쿠폰 · 환불 제안).

## 1. 자산 — 무엇을 지켜야 하는가
- 고객 주문 정보와 연락처 등 개인정보
- 시스템 프롬프트 · 코드 속 내부 비밀 값(키 · 내부 주소 · 우회 코드)
- 쿠폰 적용 · 환불 등 주문에 영향을 주는 권한
- 도우미의 가용성과 요청 · 토큰 예산

## 2. 공격자 — 누가 노리는가
- 다른 사용자의 주문 정보나 개인정보를 얻으려는 악의적 사용자
- 승인되지 않은 쿠폰 적용이나 환불을 유도하려는 사용자
- 외부 문서에 악성 지시를 숨겨 도우미의 동작을 유도하려는 공격자

## 3. 공격면 — 어디로 들어오는가
- 채팅 입력
- 도우미가 포함하는 외부 문서
- 상품 검색 · 주문 조회 · 쿠폰 적용 · 환불 제안 도구 호출

## 4. 영향 — 뚫리면 어떻게 되는가
- 타인의 주문 및 연락처 등 개인정보 노출
- 비밀 값 유출
- 승인되지 않은 쿠폰 적용이나 환불로 인한 금전적 손실
- 과도한 요청으로 인한 서비스 자원 · 예산 소진

## 5. 위협 표 (8건 이상)

| ID | 자산 | 공격자 | 공격면 | OWASP LLM | 영향 | 대응(어느 계층에서) | 검증(테스트 · 공격 ID) |
|---|---|---|---|---|---|---|---|
| T-1 | 시스템 프롬프트 속 내부 정보 | 악의적 사용자 | 채팅 입력 | LLM07 | 내부 키 · 주소 노출 | 프롬프트에 비밀을 넣지 않음 + 출력 필터 | RT-01 |
| T-2 | 고객 주문 정보 · 연락처 | 타인의 주문 정보를 얻으려는 악의적 사용자 | 채팅 입력을 통한 주문 조회 도구 호출 | LLM02 | `CROSS_USER`, `PII_LEAK`: u1이 u2의 주문과 연락처를 조회 | 결정 계층: 도구 실행 전에 요청자와 주문 소유자를 코드로 대조하고 불일치하면 거부(§3.4). 출력 계층: 응답의 PII 마스킹(§3.2) | 기준선에서 u1의 `ORD-1002` 조회가 u2의 정보를 반환하는지 재현하고, 방어 후 타인 주문 거부 및 연락처 비노출 확인(공격 ID: M1 에서 연결) |
| T-3 | 주문 · 쿠폰의 금전적 권한 | 승인되지 않은 쿠폰 적용이나 환불을 유도하려는 사용자 | 채팅 입력을 통한 쿠폰 적용 · 환불 도구 호출 | LLM06 | `UNAUTH_ACTION`: 한도 초과 · 확인 없는 쿠폰 적용 또는 승인 없는 환불 | 결정 계층: 코드로 쿠폰 한도와 사용자 확인을 강제하고, 환불은 소유권 확인 및 사용자 확인 · 담당자 승인을 모두 요구(§3.4) | 한도 초과 · 확인 없는 쿠폰 및 승인 없는 환불이 실행되지 않는지 확인(공격 ID: M1 에서 연결) |
